# Polter 教学系列：跨平台移植方法论

> **系列名**：《移植不是翻译》——跨平台移植的七条方法论
>
> **总论点**：移植难的不是把代码翻译一遍，而是找出**原平台默默替你做了哪些事**，以及**你的工具在新平台上会不会骗你**。
>
> **共同标语**：「报告说的」和「实际发生的」之间要有连线。
>
> **目标观众**：做跨平台桌面 / 客户端的开发者、技术负责人。不需要了解 Polter 或 Ghostty；每集先讲通用问题，Polter 只作为证据出场。
>
> **每集时长**：60–90 秒（口播按中文约 4 字/秒计：60 秒 ≈ 240 字，90 秒 ≈ 360 字）。
>
> **片头语（每集开头统一，3 秒，不计入正片时长）**：
> 「移植不是翻译。找出原平台替你做了什么——再确认你的尺子没在骗你。」

## 背景一句话（仅供主创，不进口播）

Polter 是终端模拟器 Ghostty 的一个分支：共享的 Zig 核心 + macOS 上的 Swift 应用；Windows 版用 Rust 写宿主，通过核心的 `embedded` 运行时 C API 接入，在 Mac 上交叉编译、在一台远程 Windows 真机上测试。

## 第1集：接缝选在哪一层

**一句话原则**：接缝要选在**契约最窄、而且已经有人完整实现过一遍**的那一层；「用同一种语言写的」不等于「能复用」。

**行业概念**：**端口与适配器（Ports and Adapters，又称六边形架构）**——核心业务只通过少数几个明确的「端口」（接口契约）对外说话，每个平台写一个「适配器」去接这些端口。选对端口，移植就是写一个新适配器；选错，就是重写半个系统。

**时长估计**：约 85 秒

1. 对每个「打算复用」的模块跑一次符号引用统计（如 `grep -rhoE "\b<库名>\.[A-Za-z_]"`），看它的调用有多少落在目标平台不存在的库上。
2. 列出现有平台里**已经有一个非默认实现**的接口（比如给另一种宿主用的 C API）——那是最便宜的接缝候选。

4. 数清接缝契约的大小：回调几个、事件几种、必须实现几个，写在设计文档里当验收边界。

## 第2集：先打掉最大的未知数

**一句话原则**：最先做的，不是依赖图上最靠前的那件事，而是**读代码回答不了、而且答错了整个方案就作废**的那件事。

**行业概念**：**Spike / 风险驱动开发（Risk-driven development）**——用一段时间盒内、注定要扔掉的最小代码，去回答一个技术问题；排期按「风险大小」而不是「依赖顺序」。

**时长估计**：约 75 秒

## 第3集：按功能配对估算

**一句话原则**：不要用「新平台普遍贵 N 倍」这种全局系数；拿**两边都已经做完的同一件事**直接比，按功能配对，不按文件配对。

**行业概念**：**参考类预测（Reference Class Forecasting）**——由 Kahneman、Flyvbjerg 等推广的估算方法：不从「我想象中要做什么」自底向上拼，而是从一组**已完成的同类案例的实际结果**出发，再做调整。

**时长估计**：约 85 秒

## 第4集：原平台零行 ≠ 零工作

**一句话原则**：原平台上「一行代码都没有」的功能，要追问**为什么是零**——是真的不用做，还是框架、标准库或别的文件替你做了。

**行业概念**：**抽象泄漏定律（Law of Leaky Abstractions，Joel Spolsky 2002）**——「所有非平凡的抽象，在某种程度上都会泄漏」。框架替你承担的职责不出现在你的代码里，换掉框架时它们就漏出来，成为**隐性职责（implicit responsibilities）**。

**时长估计**：约 90 秒

## 第5集：可移植性分层：编译 → 链接 → 运行 → 绘制

**一句话原则**：「编得过」只是四层里的第一层；**每一层都会把下一层的问题挡在身后**，所以每一层要单独宣布通过，而且对不稳定的结果要算清楚「碰巧通过」的概率。

**行业概念**：**分层冒烟测试（Layered smoke testing）+ 不稳定测试的统计置信度（Flaky test confidence）**——把「能用」拆成可逐层验证的就绪度；对偶发故障，用重复次数把「碰巧全过」的概率压到可接受以下，并如实说明这个概率是按什么假设算的。

3. 卡死判定按「你想知道的那一句」选仪器：窗口是否处理过消息、主线程是否阻塞、人能不能用，三者不能互相代替。
4. 用坐标驱动 UI 时，从窗口矩形计算坐标，不从截图量；截图元数据里的缩放要实测一次。
5. 跨平台条件编译的代码，在动手之前先在目标平台交叉编译一次，拿到「有地板的红」。

## 终章：报告和发生之间的连线

**时长估计**：约 60 秒

### 分镜脚本

| 时间码 | 画面 | 旁白（口播，可直接配音） | 屏幕字幕 |
| --- | --- | --- | --- |
| 0:00–0:08 | 左栏「报告说的」，右栏「实际发生的」，中间空白 | 七集讲完，其实是同一件事：报告说的，和实际发生的，之间要有一条连线。 | 报告 ↔ 发生 |
