# ep04：原平台零行 ≠ 零工作

- **标题（封面大字，待用户定）**：一行代码都不用写的功能，搬家后最坑
  - 备选：①「窗口一放大就一圈黑边？问题出在没人写过的那行代码」 ②「零行代码，不等于零工作」
- **封面画面**：一扇放大了的纸质终端窗口，右边和上边一圈醒目的黑边；橙色方块小人拽着窗口右下角，回头看着一行空白的虚线代码行，头顶问号。角上一张小纸条「0 行」。视频前 3 秒兑现同一个画面（0s 窗口 → 0.5s 小人一拉、窗口放大、黑边露出）。
- **一句话目标**：看完这集，观众知道原来系统上「一行代码都没有」的功能，搬家前要先问一句「为什么是零」——是真不用做，还是框架（或别的文件）替你做了；替你做的那部分，到新系统上就得有人接手。
- **受众**：对软件开发好奇的初中生及以上；做跨平台客户端的开发者也能看。旁白按初一阅读水平写，口吻学 ep01 / ep02 用户定稿。
- **时长**：旁白草稿 12 段、488 字。按任务口径（千问 Maia 4.5 字/秒 + 句间 0.6s、切镜段前 1.5s、问句 +0.3s、s03 前 3.2s 容纳系列字卡、结尾 5.6s）估 **约 140 秒**；按 ep02 实测校准（×0.83）约 **116 秒**。横版 1920×1080 / 30fps。
- **视觉风格**：沿用 ep01/ep02（纸质 UI + 橙色方块小人 + `assets/lib`）。主道具是「那圈黑边」和「虚线画框」，开头、中段、结尾各出现一次。3 处运镜：①开场窗口被拉大；②在文件纸山里找连线；③从 Windows 横移到 Linux 再横移回来。
- **配音**：千问 `qwen3-tts-instruct-flash` · 音色 Maia（同 ep01/ep02）。
- **素材来源**：`source/series-script.md`（下称「原稿」，复制自 ep01）第 4 集（:171–221）。只用原稿「事实核对」表（:205–218）里已核的事实。

**原稿有、本集没用的**：
- **无障碍 58 行 → 450–900 行，8–16 倍**（:215，已核）。为压时长暂删。草稿写法：「这样的事不止一件。无障碍功能，就是让看不见屏幕的人，也能靠读屏软件用电脑。它在 Mac 上只有五十八行，到了 Windows，估计最多要九百行。」（约 15 秒）。删的另一个原因：Mac 那边是 58 行、**不是零行**，原稿钩子「原平台上一行代码都没有的功能，到新平台可能要写九百行」把菜单的「零行」和无障碍的「九百行」混成了一句，本集不沿用这个说法。若用户想要这个大数字，建议替换掉 s09–s10 菜单那组，而不是两组都放。
- **抽象泄漏定律（Joel Spolsky, 2002）**（:218）——原稿标「通用常识，未在仓内核对」，按规则**不进旁白、不上画面**。请用户定：要不要作为行业概念出一张字卡（需另行核实）。
- 原稿钩子数字「0 行 → 450–900」见上，未用。

旁白只保留两个数字：**三次**（猜错的次数）、**一百多个**（菜单项）。1000×670、103 只上画面。

**需要用户确认的几处**：
1. #10「一行从来没人写过的代码」——严格说，设视口的函数写了，只是从没被调用；我用「没人写过的那一行」指那次调用。如果嫌不严谨，可改成「一行从来没人调用过的代码」，但对初一观众更难懂。
2. 「画框」代替「GL 视口」、「界面工具包」代替「GTK」、「光秃秃的窗口」代替「裸 HWND」——字幕角标可出 GTK。
3. s09「一行代码都没写」——原文是「0 行 Swift」，菜单做在 xib 界面文件里（xib 本身是文件，不是手写代码），口语化后是否可接受。
4. 是否把无障碍那组（58 → 最多 900）换回来，见上。
