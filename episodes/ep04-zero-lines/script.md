## s01
旁白：窗口一放大，右边和上边就多出一圈黑边。查到最后才发现，问题出在一行从来没人写过的代码上。
画面：【钩子·前 3 秒】第 0 帧：明亮的纸质终端窗口，小人拽住右下角一拉——0.5s 窗口放大，右边和上边立刻露出一圈黑边（黑边是画面主体，旁边留白）。小人愣住，头顶问号。「一行从来没人写过的代码」时，窗口下方浮出一行空白的虚线代码行，一闪。

## s02
旁白：在原来的系统上，这件事一行代码都不用写。可是，一行都不用写，不等于不用做。
画面：左边 Linux 的窗口放大，四边干干净净，贴「0 行」；右边 Windows 的窗口放大，一圈黑边。大字「零行 ≠ 零工作」停 ≥2s。说完后 1.5s 无配音系列字卡：《移植不是翻译》第 4 集 · 原平台零行 ≠ 零工作。

## s03
旁白：Polter 的 Windows 版，就碰上了这圈黑边。他们连猜了三次，三次都猜错。
画面：黑边窗口放到画面中央，小人拿放大镜；桌上摆出三张空白「猜测卡」，标 ① ② ③。

## s04
旁白：先猜窗口得先显示出来，一试，不是。再猜得一开始就按最终大小建好，改完居然好了，可那只是碰巧。又猜画布没跟着变大，一查，尺寸全对。
画面：【再抓回来 ~23%】三张卡依次翻开、被划掉，每张都有自己的小动作：①「先显示窗口」——小人拨开关对照，卡片红叉；②「按最终大小建」——黑边一度消失，小人刚要欢呼，卡片翻过来背面写「碰巧」；③「画布没跟着变大」——尺子量一下，绿色「尺寸全对」，卡片仍打叉。

## s05
旁白：最后，他们把“画框”的大小打了出来。画框，就是告诉显卡往多大一块地方画。窗口放大前后，它一直卡着没动。
画面：窗口里画出一个虚线「画框」，示意显卡只往框里画；窗口放大，框纹丝不动，框外就是那圈黑边。日志纸条高亮一行 `viewport=(0,0,1000,670)`，放大前后两条一模一样（数字只在画面上）。

## s06
旁白：再一查，负责设画框的那段代码，整个项目里，一次都没人用过。
画面：【再抓回来 ~42%】整个项目的文件堆成一座纸山，小人拿着「设画框」这张纸满山找连线——一根线都没有；计数牌「调用它的地方：0」。

## s07
旁白：那为什么 Linux 上从没出过这个问题？原来那边的界面工具包，每一帧都悄悄替他们设好画框。换到 Windows 光秃秃的窗口上，就没人管了。
画面：【反转 ~47%】镜头横移到 Linux 那边：一个叫「界面工具包」的小帮手，每一帧都偷偷把画框拉到跟窗口一样大（可出 GTK 字样做角标）；再横移回 Windows：光秃秃的窗口旁边空无一人。

## s08
旁白：修的时候，他们没加“如果是 Windows 就怎样”，而是让两边共用的画图代码，自己把画框设好。
画面：分屏：左边一张便签「if Windows …」被小人揉掉；右边 Linux 和 Windows 共用的那份画图代码里加一行，两个窗口一起放大，都没有黑边。字幕「修在共用的地方，不加平台判断」。

## s09
旁白：这样的事不止一件。比如主菜单：一百多个菜单项，全画在一张界面图纸里，一行代码都没写。
画面：Mac 菜单栏展开，一长串菜单项哗啦啦往下掉，计数跳到「103 项」；旁边代码计数牌「0 行」。菜单其实画在一张界面图纸（xib）上。（真机截图：系统菜单栏右侧账户名/设备名打码）

## s10
旁白：Windows 版原本打算干脆不做菜单栏，结果被用户当面否了：一个从没人教过的人，要怎么找到这些命令？
画面：【再抓回来 ~74%】会议白板上写着「Windows：不做菜单栏」，一只手伸进来把它划掉；大字问句「没人教过的人，怎么找到这些命令？」停 ≥2s。最后切到 Windows 标签条左侧的菜单按钮。

## s11
旁白：所以下次搬家前，把原来零行代码的功能列出来，每条都问一句：为什么是零？是真不用做，还是有人替你做了？
画面：清单纸：一列原平台「0 行」的功能，小人逐条打上问号「为什么是零？」，再分到两栏：「真不用做」「有人替你做了」。

## s12
旁白：回到那圈黑边：答案不在写错的代码里，而在从来没人写过的那一行里。
画面：【收尾】回到开头那扇窗口：小人再拉一次，窗口放大，黑边没了；那行虚线代码被填上。最后一句说完画面停 ≥2.5s，结尾字卡 ≥2.5s，干脆结束。
