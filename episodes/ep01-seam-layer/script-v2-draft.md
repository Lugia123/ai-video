# ep01 讲稿 v2 草案（按 CLAUDE.md「开头与留存」重排）

- 标题：同一个软件搬家，为什么有人要重写两万行，有人只改二十行？
- 封面：左边一座高高的纸代码山（23,669），右边一张薄纸（20），方块小人站中间扛着刀，一脸问号。
- 目标时长：约 105–115 秒；段间停顿 0.7 秒。

| 阶段 | 段 | 旁白 | 画面 / 小人 |
| --- | --- | --- | --- |
| 钩子 0–5s | s01 | 你有没有想过：同一个软件搬到 Windows 上，有人得重写两万三千多行，有人只改了二十行？ | 第 0 帧就有画面：小人抬头看，左边纸代码山一路长高到"23,669"然后轰然塌下，小人被埋又探出头；右侧飘下一张"20 行"的薄纸。兑现标题 |
| 钩子 5–10s | s02 | 差别不在谁的代码写得好，而在第一刀切在哪。这一刀怎么切，咱们现在就演给你看。 | 小人举刀，镜头俯冲到纸板层叠的架构图 |
| （字卡 1.5s，无配音） | — | 《移植不是翻译》第 1 集 · 接缝选在哪一层 | 纸条一闪而过 |
| 从说到做 | s03 | 把软件搬到另一个系统，叫移植。你得先把它切成两半：一半留着不动，一半重新写。切开的地方，就叫接缝。 | 刀沿层间比划；切开处发光 |
| 从说到做 | s04 | 接缝就像插头和插座。形状对得上，一插就能用。 | 小人拿插头插座演示，"咔" |
| 从说到做 | s05 | 很多人的直觉是，找一份最像的代码，照着搬。可同一种语言写的，不等于能拿来用。要看的是，它在调用谁。 | 两份代码并排，箭头拉出"调用谁" |
| **再抓回来 ~25%** | s06 | 来看个真实的例子。Polter 是一个终端软件，就是敲命令用的那种窗口。它的 Linux 界面，有两万三千多行代码。 | 镜头急速拉远，露出整座文件山；小人被吓一跳 |
| | s07 | 问题来了：这些代码调用的，全是 Linux 桌面那一套库，有的压根不出 Windows 版。搬过去，一行都用不上。 | 文件山上的调用线全连到 GNOME 库，逐根断开变灰 |
| | s08 | 那从头重写一套？输入法那块，得手工拼一堆底层接口。换成微软自家的界面工具呢？在开发用的 Mac 上，根本做不出程序来。 | 两张方案卡片被小人依次划掉 |
| **再抓回来 ~60%** | s09 | 最后，他们走了 Mac 版早就走通的那条路：核心只对外露出一个 C API。它就像一个大家都认的插座。 | 插座亮起；镜头沿连线平移到 Mac 宿主，再到新的 Windows 宿主 |
| | s10 | Windows 版只要做个新插头插上去。C API 这边，只多了一个窗口编号，大约二十行。 | 联合体里多出一行；"20 行"薄纸落下 |
| 收尾 | s11 | 这就是开头那二十行的来历。 | 回到开场构图：纸山 vs 薄纸，小人把插头插上，"咔" |
| 收尾 | s12 | 所以记住：接缝要选在约定最少、已经有人走通的那一层。明天就数一数，你想搬的代码，到底在调用谁。 | 小人点头竖手；字卡后干脆结束 |
