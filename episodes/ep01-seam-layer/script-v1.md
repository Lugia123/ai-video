# ep01 讲稿：接缝选在哪一层

## s00
旁白：移植不是翻译。找出原平台替你做了什么，再确认你的尺子没在骗你。
画面：片头字卡。镜头从一叠分层纸板（有厚度、带投影）的正上方俯冲推进，停成等距视角；系列名《移植不是翻译》+ 第 1 集标题落下。

## s01
旁白：你有没有想过，把软件搬到另一个系统，第一刀该切在哪？切在哪，决定了你后面要重写多少。
画面：小人从右边走进来，停在分层纸板旁，歪头冒问号；「第一刀」时掏出纸刀，镜头绕着层叠转一小段，刀在几层之间来回比划。大字「第一刀切在哪？」

## s02
旁白：这一刀切开的地方，叫「接缝」。它就像插头和插座：形状对得上，一插就能用。
画面：纸剪的插头和插座；小人指着插座，「一插就能用」时插头滑进去，咔哒。大字「接缝 ＝ 插头和插座」。

## s03
旁白：直觉是找一份最像的代码，照着搬。可同一种语言写的，不等于能拿来用，要看它在调用谁。
画面：两个纸窗口并排：左「Linux 版」满是代码，右「Windows 版」空白，中间一个带问号的箭头。小人「不等于」时歪头，「调用谁」时指向左边窗口。大字「同语言 ≠ 能复用」。

## s04
旁白：举个例子。Polter 是个终端软件，就是敲命令的那种窗口。它的 Linux 界面有两万三千多行代码。
画面：纸质终端窗口里敲一条行数统计命令，数字往上滚到 23,669；小人被吓一跳。镜头快速拉远，露出一整座文件纸堆。

## s05
旁白：问题来了：这些代码调用的全是 Linux 桌面那一套库，有的压根不出 Windows 版。搬过去一行都用不上。
画面：纸质编辑器里的代码，gtk / glib / gdk / adw / gio 的调用逐个被红笔圈出；adw 盖上「不出 Windows 版」的章；「一行都用不上」时整页变灰划掉。小人指着圈出的调用。大字「全是 GNOME 调用」。

## s06
旁白：从头重写一套？输入法那块得手工拼底层接口。换成微软自家的界面工具？在开发用的 Mac 上根本做不出来。
画面：两张方案卡片依次被红笔划掉：「从头重写 → 卡在输入法」「微软界面工具 → 卡在开发机」。小人摇头、叹气。

## s07
旁白：最后走的是 Mac 版早就走通的路：核心只对外露一个 C API，就像一个大家都认的插座。
画面：示意图：核心 ↔ C API 插座 ↔ Mac 宿主（已接好）。镜头沿着连线平移到右侧空位，那里亮起「Windows 宿主」。小人指着插座。大字「大家都认的插座」。

## s08
旁白：Windows 版做个新插头插上去就行。C API 这边只多了一个窗口编号，大约二十行。
画面：Windows 插头插进插座；纸质编辑器显示平台联合体，多出一行 `struct { void* hwnd; } windows;`，高亮。小人竖起小手。大字「C API 侧 ~20 行」。

## s09
旁白：两万三千多行，对二十行。
画面：左边一座高高的纸堆，右边一张小纸条；小人来回看两边，点头。

## s10
旁白：记住：接缝要选在约定最少、已经有人走通的那一层。明天就数数，你想搬的代码到底在调用谁。
画面：原则字卡。小人点头、竖起小手总结，然后走出画面。大字「按「调用了谁」算复用」。之后接结尾字卡（下一集预告）。
