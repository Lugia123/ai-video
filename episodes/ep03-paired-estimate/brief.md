# ep03：按功能配对估算

- **标题（封面大字，待用户定）**：「多花一半功夫」？有的功能贵三倍，有的不到五分之一
  - 备选：①「估工作量，别乘同一个数」 ②「搬到新系统要多干多少活？一个功能一个功能地比」
- **封面画面**：会议白板上「× 1.5」被一道红笔划掉；白板前两根纸柱子，一根冲到顶贴「×3.11」，一根缩成一小截贴「×0.18」；橙色方块小人站在中间，两手一上一下比划。视频前 3 秒兑现同一个画面（0s 两柱等高 → 0.4s 左柱窜高「×3.11」→ 0.9s 右柱缩下「×0.18」）。
- **一句话目标**：看完这集，观众知道估算「搬到新系统要多少工作量」时，不能拿一个统一的倍数去乘，而要找两边都已经做完的同一个功能，一个对一个地比，并且先确认数的范围没混进别的东西。
- **受众**：对软件开发好奇的初中生及以上；做跨平台客户端的开发者也能看。旁白按初一阅读水平写，口吻学 ep01 / ep02 用户定稿。
- **时长**：旁白草稿 11 段、507 字。按任务口径（千问 Maia 4.5 字/秒 + 句间 0.6s、切镜段前 1.5s、问句 +0.3s、s03 前 3.2s 容纳系列字卡、结尾 5.6s）估 **约 140 秒**；按 ep02 实测校准（同口径估 149.6s、实测 123.66s，×0.83）约 **116 秒**。横版 1920×1080 / 30fps。
- **视觉风格**：沿用 ep01/ep02（纸质 UI + 橙色方块小人 + `assets/lib`）。主道具是「四根比值柱」，贯穿全片。3 处运镜：①开场两柱弹开；②从四根柱横移到「全部加总」大柱；③终端计数器拉远露出混进去的两堆纸。
- **配音**：千问 `qwen3-tts-instruct-flash` · 音色 Maia（同 ep01/ep02）。
- **素材来源**：`source/series-script.md`（下称「原稿」，复制自 ep01）第 3 集（:125–170）。只用原稿「事实核对」表（:157–167）里已核的事实。

**原稿有、本集没用的**：
- 单价公式「n = 1 的单价，用之前要知道它是 n = 1」（:166，已核）——草稿里写过一段，为压时长删了。它讲的是「样本只有一个」，和本集主线（配对 / 基数）是第三条支线；如果想保留，可加回一段约 9 秒：「就连文档里一条估算工作量的公式，旁边也老老实实标着：它只来自一个例子，用之前心里要有数。」
- 分子只算有对应 macOS 功能面的行（:167，原稿注明「仅入清单」）。

旁白只保留三个数字：**三倍多**、**不到五分之一**（各在开头、中段、结尾出现）、**七千多行**。「多花一半功夫」是开场假设。3.11 / 1.72 / 0.23 / 0.18 / 0.88 / 43,157 / 35,755 只上画面。

**需要用户确认的几处**：
1. 开场假设「大概多花一半功夫」——原稿白板写的是「Windows ≈ Mac × 1.5」，我改成更口语的「多花一半功夫」。算不算额外引入了一个数字？也可以改成「大概多花一些功夫」，但冲击会弱。
2. s04「上一集说过」——直接回扣 ep02；如果各集要能单独看，可改为「因为 Windows 会来问一大串问题……」。
3. s05「只能自己搭」——原文是「AppKit 白送整套标签 UI；Win32 一个都没有」，「自己搭」是由此推出的口语说法。

## 打比方 / 大白话对照

| 专业词 | 片中说法 |
| --- | --- |
| 全局系数（Windows ≈ Mac × 1.5） | 「搬到新系统，大概多花一半功夫」；拿同一个数去乘所有功能 |
| 按功能配对，不按文件配对 | 一个功能对一个功能地比 |
| 比值 3.11× / 0.18× | 变成原来的三倍多 / 不到原来的五分之一 |
| TSF 手写 26 个方法 | Windows 会来问一大串问题，每个都得亲手写好回答（沿用 ep02 的比喻） |
| 标签（tab group） | 标签页：窗口顶上那排能来回切换的小页签 |
| AppKit 白送 | Mac 的系统白送了一整套 |
| 2,096 / 2,382 = 0.88 | Windows 版的代码，反而比 Mac 版还少一点 |
| 基数 / 没限定目录的 find | 原来有多少；没限定文件夹 |
| 构建产物 | 自动生成的文件 |
| 参考类预测 | 从已经做完的同类事情出发，不从「我觉得要做多少」出发 |
