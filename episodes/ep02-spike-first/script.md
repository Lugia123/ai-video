## s01
旁白：想象一下，你花了三个月搭好一个软件，到最后才发现，有一块根本做不出来。三个月，全白干。
画面：【钩子】第 0 帧：一座搭到一半的纸架子（纸条搭的脚手架 + 标着「第 1 周…第 12 周」的层），小人在顶上放最后一块。「根本做不出来」时最后一块卡住、架子晃；「全白干」时轰然塌掉，纸片四散，小人跌坐在废墟边。大字「三个月，全白干」。

## s02
旁白：怎么才能不掉进这个坑？答案有点反直觉：先做你最没把握的那件事。
画面：小人从废墟里爬起，头顶问号；「反直觉」时画面翻转，小人举起一张小纸条「先试这个」。大字「先做最没把握的那件事」。说完后 1.5s 无配音系列字卡：《移植不是翻译》第 2 集 · 先打掉最大的未知数。

## s03
旁白：Polter 做 Windows 版时，就真遇到了这种事。设计文档里列着好几个没把握的问题。其中一个被单独拎了出来：输入法那块，到底有多难搞？
画面：【再抓回来 ~25%】纸质设计文档，一串「？」条目；镜头俯冲进其中一条，红笔圈出、抽出放大：「输入法那块，到底有多难搞？」

## s04
旁白：输入法，就是你打拼音时，弹出一排候选字的那个小窗口。在 Windows 上，软件得按一套专门的规矩，跟输入法一问一答地配合。
画面：纸质窗口里打拼音 nihao，光标旁弹出候选字（你好 / 泥 / 拟…）。软件 ↔ 输入法两个气泡一问一答。角标「TSF」。

## s05
旁白：麻烦在于，这个问题没人验过，而且光靠读代码，怎么读都回答不了。整份文档里，只有它是这样。
画面：放大镜在代码纸上来回扫，问号越来越大；「只有它是这样」时其余条目都打勾，只剩这一条亮红。

## s06
旁白：怎么办？先别急着搭架子。他们先写了一小段试验代码，大约四百七十行。Windows 会来问的二十六个问题，每一个都亲手写好回答。
画面：小人放下架子纸板，拿起小纸条开写；行数计数滚到「≈470 行」；26 张问答卡一张张翻开写满。

## s07
旁白：第一次编译，只报了九个错。全是名字对不上、格式不对这种小毛病。
画面：【再抓回来 ~45%】编译按钮按下，等一拍：弹出红色大字「9 个错」；两张错条「名字对不上」「格式不对」被小人撕掉，变绿。

## s08
旁白：接下来是真考验：在 Mac 上做好的程序，拷到一台真的 Windows 电脑上。
画面：运镜：纸 MacBook → 程序纸片沿弧线飞到一台纸质 Windows 显示器。

## s09
旁白：第一次运行，就和输入法接上了头。打一串拼音，候选字的小窗口，正好落在事先算好的位置上。
画面：【大场面 ~65%】第一次运行：两边的线「咔」一下接上；镜头推近光标：打一串拼音，候选框弹出，正好落进事先画好的虚线框里，绿勾，小人跳起。

## s10
旁白：文档后来写道：这是唯一一个“先验证、再开工”的决定，而它恰好是回报最大的那个。
画面：引语字卡贴在文档上，逐句划线：「先验证、再开工」「回报最大」。

## s11
旁白：这种做法，行内叫“spike”：用一小段试完就能扔的代码，专门去回答那个最没底的问题。
画面：【再抓回来 ~80%】大字「spike」，小字「试完就能扔的小段代码」；小纸条揉成团扔进纸篓，问号变对勾。

## s12
旁白：所以下次动手前，先把要做的事分成两堆：读一读就能回答的，和不试一下就说不准的。说不准的那堆，每件配一小段试验代码，排在最前面。
画面：两栏白板：左「读一读就能回答」右「不试说不准」；便签分进两栏，右栏每张配一张小纸条，整栏挪到最前面。

## s13
旁白：回到开头那三个月：最没把握的那件事，放在第一天就去试。
画面：回到开头那座架子：这次小人先把「先试这个」的纸条试掉（变绿），架子稳稳搭起。说完 0.5s 后结尾字卡 1.5s，干脆结束。
