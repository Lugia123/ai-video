## s01
旁白：想象一下，你手上有十件事。其中有一件，一旦做不成，另外九件全白干。你先做哪一件？
画面：【钩子 0–9s】第 0 帧：九张纸便签叠成高塔，压在最底下一张红便签上，画面明亮。「一旦做不成」时红便签裂开，塔晃；「全白干」时九张哗啦塌下，小人抱头。「先做哪一件？」塔复原，十张便签摊开贴墙，其中一张发红，小人头顶问号。大字「先做哪一件？」

## s02
旁白：很多人会从最顺手的开始，一件件往下做。结果最没把握的那件，被拖到了最后。等发现它走不通，前面搭好的，全都白搭。
画面：甘特图纸条：搭架子 → 填功能 → ……镜头横向平移到最后一格「最没把握的那件」；「走不通」时最后一格变红打叉，前面各格依次变灰、卷边。说完 0.5s 后 1.5s 无配音系列字卡：《移植不是翻译》第 2 集 · 先打掉最大的未知数。

## s03
旁白：来看个真实的故事。Polter 这款软件要搬到 Windows 上，设计文档里列着好几个没把握的问题。其中一个被单独拎了出来：输入法那块，到底有多难搞？
画面：【再抓回来 ~25%】纸质设计文档一页页翻过，一串「？」条目；镜头俯冲进其中一条，被红笔单独圈出、抽出来放大：「输入法那块，到底有多难搞？」

## s04
旁白：输入法，就是你打拼音时，弹出一排候选字的那个小窗口。在 Windows 上，软件得按一套专门的规矩，跟输入法一问一答地配合。
画面：纸质窗口里打拼音 nihao，光标旁弹出一排候选字（你好 / 泥 / 拟…）。旁边出现两个小人对话气泡：软件 ↔ 输入法，一问一答。角标字幕「TSF」。

## s05
旁白：麻烦在于，这个问题没人验过，而且光靠读代码，怎么读都回答不了。整份文档里，只有它是这样。
画面：放大镜在代码纸上来回扫，扫不出答案（问号越来越大）；「只有它是这样」时整份文档其余条目都打勾，只剩这一条亮红。

## s06
旁白：怎么办？先别急着搭架子。他们先写了一小段试验代码，大约四百七十行。Windows 会来问的二十六个问题，每一个都亲手写好回答。
画面：小人放下「搭架子」的纸板，拿起一张小纸条开写；行数计数滚到「≈470 行」；二十六张小问答卡一张张翻开写满（计数 26）。

## s07
旁白：第一次编译，只报了九个错。全是名字对不上、格式不对这种小毛病。
画面：【再抓回来 ~50%】编译按钮按下，屏幕等一拍：弹出红色「9 个错」（数字大）；每条错一贴便利贴，写「名字对不上」「格式不对」，被小人三下五除二撕掉，变绿。

## s08
旁白：接下来是真考验：在 Mac 上做好的程序，拷到一台真的 Windows 电脑上。第一次运行，就和输入法接上了头。打一串拼音，候选字的小窗口，正好落在事先算好的位置上。
画面：【大场面 ~70%】纸 MacBook → 程序纸片飞到一台 Windows 真机（纸质显示器）。第一次运行：两边伸出的线「咔」一下握上。镜头推近光标：打一串拼音，候选框弹出，正好落进事先画好的虚线框里，严丝合缝，绿勾。

## s09
旁白：文档后来写道：这是唯一一个“先验证、再开工”的决定，而它恰好是回报最大的那个。
画面：引语字卡（纸条贴在文档上），逐句划线：「唯一一个先验证、再开工的决定」「回报最大」。停留 ≥2s。

## s10
旁白：这种做法，行内叫“spike”：用一小段试完就能扔的代码，专门去回答那个最没底的问题。
画面：大字「spike」，下面一行小字「试完就能扔的小段代码」；小纸条被揉成团扔进纸篓，问号变成对勾。

## s11
旁白：所以下次动手前，先把要做的事分成两堆：读一读就能回答的，和不试一下就说不准的。说不准的那堆，每件配一小段试验代码，排在最前面。
画面：两栏白板：左「读一读就能回答」右「不试说不准」；便签分进两栏，右栏每张配一张小试验纸条，整栏挪到排期最前面。

## s12
旁白：回到开头那十件事：先做的，就是那件一旦做不成、其余全白干的。
画面：回到开头那面墙：小人先把那张红便签摘下、试一下 → 变绿；另外九张稳稳叠上去。说完 0.5s 后切结尾字卡（下一集预告，1.5s），干脆结束。
