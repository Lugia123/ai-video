## 2. 再测一轮

### a) 干净环境重建

目的：证明 puppet 真的自成一体。

```
1. 把 puppet/ 整个拷到一个空目录（比如 /tmp/puppet-clean/）。不带 ep09、不带 proto-b、不带 assets。
2. 只按 README 的命令做：
   a. 装依赖（npm install；playwright 装浏览器）
   b. puppet check characters/beret-girl      → 数据包通过 schema 校验、贴图都在
   c. node --test                              → 单元测试
   d. puppet demo characters/beret-girl --twice → 渲演示片两遍，逐帧 md5
   e. 和仓库里现有的演示片逐帧比
3. 记录每一步的输出。
```

判定：

- 任何一步去读了拷出来的目录以外的文件 → **不过**。怎么抓：渲染用的本地服务器只服务这个目录，任何 404 都记下来；另外跑一遍 `grep -rn "episodes/\|proto-b\|\.\./\.\./" .` 必须没有结果（文档里提到历史路径的除外，列白名单）。
- 两遍 md5 不一致 → 不过。
- 和现有演示片逐帧比：同一台机器上应当逐帧相同；不同就查是哪一步引入的。**换一台机器是否逐帧相同我不承诺**（软件渲染的版本、系统字体都可能不同），那种情况改用「差异像素比例低于阈值」并写明阈值。
- 系统依赖（ffmpeg、Python 的 PIL / numpy / scipy、中文字体）写进 README 的「前提」一节；缺了要报清楚的错，不能悄悄出错图。

### b) 回归检查清单

把今天用户逐条指出的问题变成可以重复跑的检查。入口统一成一个命令（设想：`puppet regress characters/<id>`），输出一个目录：每条检查一张固定取景的图 + 一份 `report.json`（每条：自动判的结果，或「需人看」）。

「怎么判」分两种：**自动** = 脚本给出过 / 不过；**看图** = 出固定取景的 1:1 图，人看。能自动的尽量自动，但我不想为了凑自动化写出会误判的规则——下面如实标了。

约定：

- 每条检查的取景、角度、放大倍数是**固定的**，写在一个配置里；换角色时只改锚点，不改取景规则。这样每次出的图能和上一次并排比。
- `report.json` 里每条写：判定方式、数值、阈值、通过与否、对应的图。阈值第一次由人看着图定，记下是谁、哪天、看的哪张图定的。
- 「看图」的条目汇成一张总表（一屏能看完），标上「上次看是哪天、谁看的」。
- 白名单（已裁定不修的）单独一个文件，每条带原因和日期。

### c) 新角色试跑（M4）

目的：验证「给一张新的设定图，就能从项目里生成一个可动角色」这句话现在成立到什么程度。

- 输入：一张新的设定图（请总管 / 用户给，最好和贝雷帽女孩差别明显：长发或双马尾、没有帽子或换一种帽子、不同的服装），加 `brief.json`。
- 走 `docs/new-character.md` 的每一步，**只用 puppet 里的脚本**。
- 边走边记一张表：

| 步 | 命令 | 耗时（机器 / 人） | 人看了几次 | 重做了几次 | 卡在哪 / 改了什么脚本 |
| --- | --- | --- | --- | --- | --- |

- 产出：第二个数据包、它的自检演示片、b) 的回归报告、这张记录表、按实际情况改过的 `new-character.md`。
- 通过标准（沿用 `ARCHITECTURE.md` f 节 M4）：引擎代码零改动；流水线脚本里没有针对这个角色的特判；人看的次数和设计里列的做对比，超了就写明为什么。

**如实的预期**：我认为 M4 第一次走**不会顺**。理由：现在的数据包是迁移脚本从贝雷帽女孩的旧文件转出来的，流水线各步是四个人各自迭代出来的、没有合在一起跑过；特征点是人工读的；「用多角度原画拟合深度和关键形」那一步还没有任何实现（现在只有按深度平移）；身体分层没接入。所以 M4 的价值主要是**把卡点一条条暴露出来**，而不是一次产出一个能用的新角色。建议把它定成「试跑 + 记录」，不设「一定产出可用角色」的目标。

## 3. 工作量和风险（粗估，没有细算）

| 块 | 量级 | 主要风险 |
| --- | --- | --- |
| 1.1 运行时搬进来 | 半天到一天 | host 拆分时默认行为被改坏。对策：搬前搬后演示片逐帧比 |
| 1.2 流水线搬进来 | 每人半天到一天，可并行 | 脚本里写死的东西比预想多；有的步骤其实是人手调出来的、没有脚本。对策：搬不动的如实写「这一步目前是手工」 |
| 1.4 文档和 schema | 半天 | schema 和实际数据包对不上。对策：以实际数据包为准 |
| 2a 干净环境 | 两三个小时 | 漏掉的隐性依赖（字体、Python 包、生图服务） |
| 2b 回归检查 | 一天左右；其中新写的自动判约 6 条 | 自动判的阈值标不准，误报或漏报。对策：标不准的退成看图，不硬凑 |
| 2c 新角色试跑 | 不好估，至少一天，很可能更多 | 见上面的「如实的预期」 |

没有包含的：物理、多角度贴图套切换、分层身体接入、用特征点拟合关键形——这些是功能，不是整理，按 `ARCHITECTURE.md` 的里程碑另排。
