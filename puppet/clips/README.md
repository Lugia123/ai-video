# clips：片段式动作（初步演示）

动作不是拆件变形，而是预先做好的透明序列帧：**归位帧 → 播 in 段 → 停在动作姿势 → 播 out 段 → 回到归位帧**。

| 文件 | 作用 |
| --- | --- |
| `demo.html` | 演示页。双击可开；被浏览器拦了就在 `puppet/` 下 `python3 -m http.server 8000`，开 `http://localhost:8000/clips/demo.html` |
| `player.js` | 播放器：状态机（归位 ⇄ 动作保持、排队 / 直接跳）+ 固定时间线（`seek(t)` 用，t 的纯函数）+ 静止帧贴片 |
| `sync.py` | 片段库体检、量包围盒和留白、生成 `clips.js`。**改了 `clips.json` 或换了帧之后跑一遍** |
| `import_i2v.py` | 把一个动作的去程 / 回程两段图生视频入库：抠像、逐帧对归位帧校色、保持帧取生成帧、接缝过渡 |
| `model_matte.py` | 调局域网生图服务的抠图模型，给视频每一帧出主体蒙版（给 import_i2v.py 当裁判用） |
| `matte_audit.py` | 抠图体检：逐帧找键色残留、亮边、半透明脏边、被吃的主体、闪烁，出三种底色的 3 倍放大清单图 |
| `bake_patches.py` | 用角色已有的分层素材，给静止帧烘口型 / 眨眼贴片（对位、对色、羽化、避开挡在脸前的手） |

片段库在角色目录里：`characters/<角色>/clips/`（`clips.json`、`clips.js`、`frames/`、`patches/`、`provenance.json`）。

`frames/` 和 `patches/` 里的图不进 git（素材要另外取得；贴片可以用 `bake_patches.py` 从分层素材重新烘出来），`clips.json` 等小文件照常入库。没有这些图时演示页会在「状态」一栏报加载失败。

## 颜色基准和入库规矩（新片段都照此）

整套片段只认**一张**关键图：归位帧。它既是位置基准，也是唯一的颜色基准。

- **只有归位这一头换成关键图**：去程第 0 帧、回程末帧 = 归位帧原图（像素级相同，和待机接得上）。
- **动作保持帧用生成帧**，不用生成视频时喂进去的那张姿势关键图：保持帧 = 回程的第一张生成帧。姿势关键图和归位帧是分两次画的，肤色、衣服深浅都不一样，拿它当保持帧，进出保持就是一格亮度跳变（2026-10-07 用户看到的就是这个：背心 / 裙子进保持时一步亮 13 个色阶）。
- **颜色只对归位帧校**：每一帧各自拟合「这一帧 → 归位帧」的逐通道曲线再套上去。不要「首帧对首关键图、末帧对末关键图、中间插值」——那样会把姿势关键图的色偏也插进片段里。
- 去程末生成帧和回程首生成帧不是同一张图：之间插 3 帧交叉淡化，接在去程末尾（每次做动作只在刚进保持时淡一次）。
- 回程最后 3 张生成帧逐步混向归位帧原图，把「换回关键图」那一步清晰度 / 线条位置的跳摊开。
- 抠像：键色线性算 alpha、半透明处还原前景色、半透明边的颜色换成最近的不透明像素色；抠图模型的蒙版只当裁判（保护运动模糊的手和白袖子、打开淡粉色的小洞）。归位帧自己的边也清一遍。
- **放行规矩（2026-10-08 定）**：改了抠图 / 校色的任何一步，放行前必须渲一段**人物 1:1 不缩放**的连续片（浅底、深底各一遍），整个人、整段动作看过；不能只凭 `matte_audit.py` 的读数和几处小块的放大图。那天的教训：亮边、被吃、淡键色全在变好，用户一看「像马赛克一样裂开了」。
- 可选、**默认关**的两项（都没通过连续观看的验收，别默认开）：
  - `--static-lock` 静止锁定：相对归位帧没动的像素直接用归位帧的。**已搁置。**做动作时头和身体会跟着晃几个像素（挥手第 14 帧头横移 7px），大片同色的地方（帽子）被一块一块认成「没动」贴回归位帧的像素，旁边的块还是移了位的生成帧，人就成了错位的马赛克。要再用，只能整帧都没动时整帧换归位帧，或者先做位移对齐。
  - `--edge luma` 轮廓按亮度重建：视频是 H.264 4:2:0，硬边上亮度 1.1px 过渡完、色度要 2.5–3.8px，所以按键色算的边又宽又有台阶；这一项把边上拿不准的像素改按亮度算。单看放大图边更干净，但和静止锁定是一起上的，没有单独做过连续观看的验收。
- 底色不是键色（比如中灰）时用 `--no-chroma`：alpha 完全靠模型蒙版，没有键色这第二道保险。
- 抠图模型的请求和视频生成不是一类，服务每切一次要卸载重载模型：**蒙版整批一次发完**（`model_matte.py --parallel=N` 把一整段同时排进队列），不要零散插在别人的视频任务之间。

这些都在 `import_i2v.py` 里，不用手做。

## 加一个动作

1. 生成两段键色底的首尾帧视频（去程：归位帧 → 姿势；回程：姿势 → 归位帧），和画布同尺寸。
2. 在 `clips.json` 的 `poses`、`clips`、`actions` 里各加一项占位（照着现有的写）。
3. 出模型蒙版（可选但建议）：`IMGGEN_URL=… IMGGEN_TOKEN=… /usr/bin/python3 clips/model_matte.py <视频> <蒙版目录>`，去程、回程各一次。
4. `python3 clips/import_i2v.py characters/<角色>/clips --action <动作> --go <去程.mp4> --back <回程.mp4> --model-matte <去程蒙版目录> <回程蒙版目录>`
5. 对着帧核一遍 `active`（有效帧范围）和 `dupes`（像重复帧的帧号），然后 `python3 clips/sync.py characters/<角色>/clips`。
6. 要口型 / 眨眼：`python3 clips/bake_patches.py characters/<角色>`，再 sync 一遍。
7. 体检：`python3 clips/matte_audit.py characters/<角色>/clips --out out/matte.png`（抠边），`python3 qa/clips/checks.py …`（接缝、漂移）。

演示页的按钮按 `actions` 自动生成，不用改代码。

## 渲染

```
node tools/render.mjs clips --page demo.html                                # 固定演示：第 1 遍全部帧，第 2 遍只播有效帧
node tools/render.mjs clips --page demo.html --query 'bg=dark'               # 深色底版（看抠边）
node tools/render.mjs clips --page demo.html --query 'demo=dupes'           # 第 2 遍改成跳过重复帧
node tools/render.mjs clips --page demo.html --query 'demo=patch&zoom=1'    # 静止帧上说话 + 眨眼，放大看脸
```

页面遵守 `qa/clips/README.md` 第 2 节的约定：全部帧（含草稿片段和贴片）解码完 `window.__video.ready` 才兑现，`seek` 同步画、缺帧就抛错。

## 静止帧上的贴片

`bake_patches.py` 给每张静止帧（归位帧、各动作保持帧）烘：四个口型、眨眼、干净脸（擦掉眼、眉、嘴）。播放器只在静止帧上贴，片段播放中不贴。

- `opts.talk` / `opts.blink`：按 `clips.json` 里固定的节拍说话、眨眼。
- 视图上直接指定：`view.mouth = 'closed' | 'small' | 'big' | 'smile' | null`（优先于 talk；`null` = 不贴，露出原来的嘴；不给这个键 = 照 talk）；`view.clean = true` 先贴干净脸，上面再叠什么（替换眼、眉）由调用方自己画。
- **表情脸**（同画风的整套表情五官，代替在干净脸上画矢量眼嘴）：来源图在 `characters/<角色>/faces/<表情名>.png`（改图模型出的「只改了表情的头」，由 `register_faces.py` 配准回头部母版），有这个目录 `bake_patches.py` 就给每张静帧烘 `poses.<名>.patches.face.<表情名>.{eyes,mouth}` 两块：眼眉（含腮红）一块、嘴一块。`view.face = '<表情名>'`（交互是 `opts.face`）贴上去，优先于干净脸和眨眼；同时有口型要画（`view.mouth` 或 talk）时嘴那块不贴，让位给口型贴片。被刘海盖住的部分不取，帧里自己的刘海仍在最上面。
  新增 / 重抽表情：改 `characters/<角色>/clips-work/faces/prompts.json`，改图**攒成一批一次发**（和视频任务互相挤模型），再 `python3 clips/register_faces.py characters/<角色> <改图结果目录> --pick 表情=种子,…`，然后重烘各库。
- 保持帧或归位帧一换，贴片要重烘（对位和肤色补偿是对着那张帧量的）。
- 别的库：`python3 clips/bake_patches.py characters/<角色> --lib clips-draft2 [--poses think,shrug]`。静帧按 `poses.<名>.frame` 读，可以指进片段里的某一帧；写回 `clips.json` 时重新读盘、只动 `poses.<名>.patches` 和库级的 `mouthShapes / talk / blink`。
- 静帧自己张着嘴、闭着眼也能烘：整块落在五官区域里的差异当成表情变化（贴片照盖），从五官区域外面伸进来的大块才当遮挡（手），贴片在那里让开。

## 动作进行中也贴表情：逐帧头部跟踪

`python3 clips/track_head.py characters/<角色>/<库> <片段>… [--no-paste 转圈的片段,…]` 给片段的每一帧量「归位帧 → 这一帧」的相似变换（平移 + 旋转 + 缩放），连同一张遮罩小图（脸的范围里去掉刘海和挡在脸前的手）和权重 w 存进 `clips.json` 的 `headTracks[帧文件]`。播放器在片段播放中遇到有跟踪且 w > 0 的帧，就把**归位帧那份贴片**（口型、眨眼、表情脸、脸部动画）按这一帧的变换画上去、按遮罩裁、乘 w；眉那一块最后单独画在刘海上层。没有跟踪数据的库照旧——片段播放中不贴。
换了片段的帧要重跑；它读归位帧的 `patches.align`，所以排在 `bake_patches.py` 之后。读数（每帧内点、残差、眼角嘴角对位后还差多少、被挡比例）都在 `headTracks` 里。

### 脸前遮挡物（手、袖子、头发盖在脸上时贴片要让开）

通用做法，不认具体动作，都在 `track_head.py` 里（说明见文件开头）：贴片占地收小（眼、眉、嘴各自成块，腮红单独一块用正片叠底）+ 每帧一张「脸前遮挡物」遮罩。遮挡物 = 相对归位帧的「新东西」（容许 ±2px 错位）里，五官范围外成块的，加上从它们往五官范围里按同类颜色连成片长进去的，再补上围住的洞和被睫毛吃掉的描边；时间上去掉单帧冒出的块。
新动作入库后看两样自动读数（`headTracks[帧]`）：`yield_eye_px`（眼眶里被让开的像素；没东西挡着时应为 0，否则露出原来的眼睛）和 `cover_alien_px`（贴片会盖住的白 / 藏青像素；应接近 0，否则盖住了袖子）。
`python3 clips/occlusion_test.py <库> --clean <没遮挡的片段> --hand <片段>:<帧>` 是合成测试（把手、拳头、袖子、袖口、头发贴到脸上已知位置，量漏报和误让）；`python3 clips/patch_leak.py <库> <片段> <逐帧渲染图目录>` 量贴表情后眼眶里残留的原帧像素。
自查时另跑一遍「回绕色块」检查（渲染图里脸上出现高饱和的青 / 品红 / 黄绿像素）：2026-10-08 垫层加时间平滑后数值超出 0–255、没夹住就转 uint8，第 23 帧脸上冒出青色块，读数和缩略图都没发现，是 3 倍逐格看到的。
已知盲区：整个落在眼眶范围里、和外面不相连的东西（悬空的小物件）认不出，和原帧自己闭眼分不开；遮挡物的描边压在睫毛上的那一段会缺。

## 以后生成时怎么让抠图省事

- **键色**：这个角色身上没有品红（腮红、舌头的粉 `min(R,B) − G` 都是负的），品红仍然可用；绿不行（头发是薄荷绿），蓝不行（藏青衣服）。换角色先量一遍角色身上有没有 `min(R,B) − G > 0` 的颜色。
- **真正的麻烦不在键色，在图生视频本身**：快速运动的手会被画成和底色混在一起的一团（运动模糊），窄缝（手和裙子之间、腋下）会被画成淡粉色而不是底色。这两样单靠键色分不开，要靠抠图模型的蒙版当裁判——所以每段都出模型蒙版。
- **让缝别太窄**：关键图里手和身体之间留出明显的空（≥ 10px），或者干脆贴住不留缝；3–8px 的缝最容易被画成半透明的淡粉色。
- **分辨率和边宽**：描边在 832×1104 下只有 2–3px，半透明边带约 1.4px，占了描边的一半；人在画布里越小，边越难干净。画幅加留白的同时别让人物像素掉太多。
- **动作别太快**：一格里手移动超过约 30px 就开始糊；宁可让动作多占几帧，播放时再跳帧加速。

## 已知限制

- 片段播放中嘴和眼是画死的；口型、眨眼只能贴在静止帧上（普通眨眼就用这个贴片；单眼眨眼之类的表情动作不在此列）。没有表情切换和漫符。
- 「直接跳」是硬切。
- 带底的草稿片段（`opaque`）只能单独看，和归位帧接不上。

## 脸可换程度（2026-10-09）：facePaste / browSwap / faceBlank

每张静帧（`poses.<名>`）、每段片段（`clips.<名>`）带三个开关（`clips/face_attrs.py` 写进 `clips.json`；`pipeline/clips/dress.py` 的 2c 步自动跑）：

| 开关 | 含义 |
| --- | --- |
| `facePaste` | 能不能往脸上贴眼 / 嘴 / 口型 / 眨眼。否 = 脸是画死的（转圈）：动作中不贴，开头 / 结尾各 3 格把相邻静帧的脸原位淡出 / 淡入 |
| `browSwap` | 能不能换眉。否 = 只换眉以外的，表情脸里自带的眉也不画（眼块里扣掉，`bake_patches.py`）；与相邻静帧不同时前后 3 格眉淡入 / 淡出。老库没有这个字段就退回 `browOk` |
| `faceBlank` | 片段本身是空脸（没画五官），整张脸全由贴片画：没指定表情画默认脸，指定了画表情脸（含它的眉）；口型、眨眼照旧 |

派生 `faceClass`：1 = 空脸，或 facePaste + browSwap 都行（表情随便换，含眉）；2 = 自带表情、只能换眉以外的；3 = 不可替换（转圈）。
建议值由程序给（片段 facePaste = 逐帧跟踪有可贴帧；静帧 = 烘过表情脸；browSwap、faceBlank 一律建议否）；人工覆盖写 `<库>/face_attrs.json`（支持通配，如 `{"clips": {"think*": {"browSwap": true}}}`，覆盖过的记在 `attrManual`）。
讲解员 `host.check()` 对「不可换脸的片段上写了表情 / 说话」「不换眉的动作上写 brow: true」给提醒。

### 空脸库

`clips/make_blank_lib.py` 把空脸归位帧 + 空脸片段搭成库（首末帧必须和空脸归位帧逐像素相同）；`dress.json` 里记 `blank: true`（头部跟踪放宽门槛、可贴帧权重一律 1，脸上没有五官只靠帽子头发定位）、`alignFrom`（贴片对位沿用有脸那版）、`origRest` / `noBrow`（原归位帧，默认脸和眉色取自它）。
`clips/make_default_face.py` 做默认脸贴片（`poses.<归位>.patches.defaultFace = { base, brow }`）：直接取原归位帧的像素，范围 = 空脸帧和原帧不同的全部像素（含贴片边界的瑕疵），所以「空脸归位帧 + 默认脸」与原归位帧逐像素相同——脚本里验证并把读数写进 `verified`（不同像素数、最大色差，应为 0）。眉那一块单独成一层，画在刘海上层。

### 面部遮罩做法（空脸库，`bake_patches.py --ink`、`track_head.py --ink-mask`，dress.json `ink: true`；2026-10-10）

空脸库的贴片不再带肤色底、发边、脸轮廓：贴上去的只有五官自己的墨迹（`patches/<归位>/*_ink.png`、`ink.default`、`ink.blink`），让「脸」整个来自片段这一帧自己的像素。
每帧一张面部遮罩（`track_ink/`，左半 base、右半 top，`headTracks[帧].maskInk`），由 `clips/face_mask.py` 从**这一帧自己**算：
- base（眼、鼻、嘴、腮红）= 这一帧里含鼻点的肤色连通区域，限制在按 headTrack 搬过来的归位空脸轮廓外扩 8px 内，再往外放 3px、**只放进发色像素**——五官多露一点压到头发边上可以，切五官、改头发不行；
- top（眉，画在刘海上层）= base ∪ 脸附近的发色像素；
- 遮挡物（手、袖子、袖口、任何脸前多出来的东西）一律不在遮罩里，外扩 2px 内一点墨迹都没有；拿不准的按遮挡物处理（鼻点被盖住就取轮廓内最大的一块肤色）；
- 时间上去掉单帧冒出的突起，不补单帧缺口（缺口可能就是真遮挡）。
播放器按 `lib.faceMode = 'ink'` 走这条路；`?faceMode=legacy`（`opts.faceMode`）退回旧的「底块 + 发边修补」。
读数：
- `clips/face_mask_real.py <库> <片段>…`：真实片段逐帧「五官落在遮挡物上的像素」（目标 0）。遮挡物真值用独立的两条（比搬过来的空脸多出来的、非肤色非发色的不透明像素），**默认扣掉挨着发丝 2px 内的描边**（那是头发自己的轮廓线，五官压到头发边上是允许的）；`--strict` 不扣；`--viz 目录` 存有落点的帧的 4 倍放大。
- `clips/face_mask_test.py`：合成遮挡测试（把手、拳头、袖子、袖口、一缕头发按已知位置贴到干净帧上），分开报「画到遮挡物上」和「被误让开」。`FACE_MASK_GUARD=n` 改遮挡物外扩的核直径（默认 5）。合成图里抠出来的手 / 拳头自带一圈脸色 / 发色的抠边像素，会算进「画到遮挡物上」，不是全部真漏；一缕「发色」遮挡物按设计就允许压（算发丝）。
- `clips/track_rel_jitter.py`：五官相对头上固定点的逐帧抖动。

### 两遍法（#1274 起）：定位用有五官那遍，贴脸画在空脸那遍

空脸片段上五官定位只能靠帽子头发推，头不是刚体，五官会晃（相对抖动 0.90px 是这套的底）。两遍法：
1. A 遍 = 有五官归位帧生成的片段（好定位）；
2. `pipeline/clips/control_video.py` 从 A 做控制视频（线稿擦掉眼眉嘴的线 / 不擦 / 剪影；纯 CPU，逐帧用头部相似变换 + 眼嘴模板匹配定擦除区）；
3. 服务器用控制视频 + 空脸归位帧生成 B 遍（`/control2video`，同运动、没五官）；
4. `pipeline/clips/two_pass.py` 建库：`track_head.py --src-a 片段=A帧目录 --rest-a 有五官归位帧` 对 A 的帧跟踪（眼嘴看得见，SIFT 点多），变换原样记到 B 同名片段的 `headTracks` 上（条目带 `trackedFrom: 'A'`）；遮挡物、面部遮罩仍逐帧从 B 这一帧自己算；
5. `pipeline/clips/accept_render.py <库> <输出目录> --old-lib <旧库> --old-act 前缀=旧动作` 出验收片（default / angry / talk × 1:1、head3x，十字标版，旧|新并排）。审看用：`tools/render.mjs` 认环境变量 `RENDER_CLIP='x,y,w,h'`（只截一块，配 `--scale`）和 `RENDER_META=1`（每帧旁存播放器画的是哪个帧文件）。
A、B 要同帧数、同尺寸（832×1104）；B 的首末帧要和空脸归位帧逐像素相同（`03_key.py` 抠完就是）；A 的首末帧换成有五官归位帧。

#### 两遍法的读数脚本和「逐五官」开关（#1274）

- `clips/track_rel_jitter.py`（固定点 = 帽子 / 发卡）和 `clips/track_rel_jitter_face.py`（固定点 = 归位帧脸轮廓上的下巴、两颊、刘海下缘，逐帧在 B 自己的帧里找）：贴上去的眼角 / 嘴角相对固定点的逐帧抖动（高频残差 RMS、二阶差 RMS）。两条都认 `--perfeat`（再加 headTracks[帧].feat）。公平对比只在「同一条 B、不同跟踪」之间做；不同动作的片段不能直接比。
- `clips/face_mask_hand_check.py <库> <片段> <起-止> <输出目录> [--step n]`：手 / 袖子压到脸的帧，4 倍放大图（黄线 = 遮挡物轮廓围起来的区域，红 = 落在区域里的五官墨迹）+ 逐帧读数。手压脸以它为准；`face_mask_real.py` 的真值认不出「手心和脸同色、描边有缺口」的地方。
- `clips/face_mask.py` 的 `hand_region`：非鼻点的肤色块 ≥60% 落在遮挡物轮廓区域里的不算脸（`FACE_MASK_HANDIN`），连鼻点那块里落在区域里的也不画（`FACE_MASK_HANDALL`，默认开）。
- 逐五官（默认关）：`two_pass.py … --per-feature`（dress.json `perFeature: true`）→ `track_head.py --per-feature`：A 这一帧按整头变换转回归位帧坐标，左眼、右眼、嘴各自对归位帧模板做 ±10px 模板匹配（亚像素），偏移（相对整头变换的残余，帧坐标）经 3 帧中值平滑（只去单帧毛刺）存 `headTracks[帧].feat = {eyeL, eyeR, mouth: [dx, dy]}`；匹配分 < 0.6 或偏移 > 8px 的帧用相邻好帧插值。播放器 `?perfeat=1`（或 `opts.perFeat`）才用：眼、眉、腮红按鼻点横坐标分左右两半各加同侧眼的偏移，嘴（中心在嘴参照点以下 12px 内及以下的贴片）加嘴的偏移，鼻点不动。`clips/feat_report.py` 报偏移幅度和平滑前后差，`clips/feat_residual.py` 用 ECC（和 track_head 不同的算法）重新量 A 里五官的实际位移，报刚性 / 逐五官残差。
- `pipeline/clips/accept_render.py … --perfeat`：只出 刚性 | 逐五官 并排（default / angry × 1:1 / head3x）。
